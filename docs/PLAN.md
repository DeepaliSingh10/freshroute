# FreshRoute — 15-Hour Winning Plan

**Problem:** PS 03 — FreshRoute: Intelligent Decision Support for Perishable Produce Distribution.

**Goal:** a winning submission that (a) fully satisfies every mandatory MVP item, (b) ships
several optional extensions, and (c) maximizes the rubric — *spoilage reduction, demand
fulfillment, net economic outcome, feasibility, robustness, reproducibility, explainability*.

**Constraint:** 3 people, 15 wall-clock hours, full web app (React/TS frontend + API),
synthetic data generated by us.

---

## 0. The one thing judges reward

FreshRoute is only interesting if it **beats a baseline on the same cost model with zero
constraint violations**. Everything else (UI, forecasting, uncertainty) is packaging.
So the plan front-loads: *data + cost model + optimizer + baseline*, then wraps it.

**Non-negotiables (locked before hour 1 of coding):**
- One frozen **data schema** and one frozen **cost model** (see `DATA_SPEC.md`).
- One frozen **baseline strategy** definition.
- All evaluation numbers **reproducible from a seed + config hash**.

## 7. Definition of Done (per metric — see `EVALUATION.md` for formulas)

- **Spoilage:** optimized spoilage < baseline spoilage on hidden scenarios (report % reduction).
- **Demand fulfillment:** fulfillment ≥ baseline; unmet demand reported consistently.
- **Net economic outcome:** optimized net revenue > baseline under one shared cost model.
- **Feasibility:** **zero** hard-constraint violations (asserted in tests + UI badge).
- **Robustness:** positive delta persists across perturbed scenarios; worst-case reported.
- **Reproducibility:** `seed + config` reproduce identical `results/*.json`.
- **Explainability:** 100% of dispatches and discounts carry a reason string.

## 8. Risks & mitigations

| Risk | Mitigation |
|------|-----------|
| Cost model mismatch with organizers | Keep cost model in **one config file**; swap values without code changes |
| LP infeasible / slow | Add slack/soft constraints with penalties; cap problem size; time-limit solver |
| Scope creep into real distributor integration | Explicit cut list below |
| Demo fails live | Pre-generated scenario + recorded backup + one-command reproduce |
| Solo bottleneck in Workstream A | B writes tests against the frozen interface; C mocks from day 1 |

## 9. Cut list (say NO during the 15h)

- ❌ Real GPS/TMS/ERP integration, live distributor APIs
- ❌ Cold-chain IoT hardware
- ❌ Fancy ML forecasting models (baseline/seasonal is enough to score E1)
- ❌ Auth, multi-tenant, persistent cloud DB (in-memory/JSON/SQLite is fine)
- ❌ Perfect price elasticity modeling (disclosed rule-based discounts score M4/E2)

Everything serves one story: **"Here is the plan, here is why each dispatch and discount
happened, and here is how much cheaper it is than the baseline — with zero rule violations."**
